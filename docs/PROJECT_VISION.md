# WayToMoksha Project Vision

## Project Purpose

WayToMoksha is a non-religious, non-profit voluntary organization focused on mindful meditation, vegetarianism, inner awareness, spiritual growth, and service-driven community work.

The website and future platform should help WayToMoksha become more organized, accessible, trustworthy, and scalable while preserving the simplicity needed for users across India, the US, and other regions.

## Core Philosophy

WayToMoksha is content-rich and community-driven. The platform should not feel like a generic NGO template.

The design should be built around real content:

- Mission
- Daily meditation sessions
- Retreats
- Donations
- Volunteer onboarding
- Guided journey for new users
- Community participation
- Future dream analysis workflow
- Future mentorship flow

Content should drive the design.

## Project Roadmap

WayToMoksha will be developed in four major projects.

### Project 1: Public Website

The first deliverable is the public website.

The website should:

- Explain what WayToMoksha is
- Present the organization mission and vision
- Show daily sessions and schedules
- List upcoming and past retreats
- Provide donation options
- Provide volunteer registration/intake
- Provide contact information
- Act as the source of truth for users

### Project 2: Volunteer Management System

The volunteer system will allow volunteers to:

- Register interest
- Select areas of contribution
- Go through human onboarding
- Get assigned a volunteer role
- Log availability
- Update recurring or temporary availability
- Support future task assignment

Volunteer categories may include:

- General volunteer
- Zoom/session support
- Video editing
- Retreat support
- Dream analysis support
- Analyzer
- Decoder

### Project 3: Dream Analysis Workflow

This system will support the dream submission and analysis lifecycle.

The current WhatsApp-based model should not be replaced immediately because many users are already comfortable with WhatsApp.

Instead, the system should use a dedicated WhatsApp number as intake.

High-level flow:

1. User sends dream details through WhatsApp to one official number
2. System creates a case
3. Analyzer reviews the case
4. Analyzer asks follow-up questions if needed
5. Case gets assigned to a decoder
6. Decoder prepares response
7. Response is sent back to user

The goal is to improve privacy and structure without hurting usability.

### Project 4: Community Hub / WhatsApp Consolidation

This is a future roadmap item.

The long-term goal is to reduce dependency on many WhatsApp groups by making the website the central hub for:

- Schedules
- Retreat updates
- Community information
- Daily practices
- Session links
- Official announcements

This should not be mixed into Projects 1, 2, or 3.

## Product Principle

Ship useful versions quickly.

Avoid overengineering.

Start lean, validate with volunteers/admins, then improve.

## Development Principle

Use AI-first development.

The human role is to guide architecture, requirements, workflows, user experience, and review.

Cursor should help write code.

ChatGPT should help with architecture, product thinking, requirements, and review.
