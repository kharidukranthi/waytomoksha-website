# WayToMoksha Roadmap

## Guiding Principle

Build in phases.

Do not mix future platform features into the first website build.

The first goal is to ship a clean, useful public website.

## Phase 1: Website Foundation

Goal:
Create the public-facing website.

Deliverables:

- Home page
- About page
- Daily Sessions page
- Retreats page
- Volunteer page
- Donate page
- Contact page
- Shared header and footer
- Responsive design
- Basic content from current website and WhatsApp screenshots
- Placeholder areas where admin confirmation is needed

Success criteria:

- Website clearly explains WayToMoksha
- Users can understand daily sessions
- Users can find upcoming retreat information
- Users can donate
- Users can express volunteer interest
- Users can contact the organization

## Phase 2: Website Enhancement

Goal:
Improve the website after admin review.

Potential enhancements:

- Better retreat detail pages
- Retreat image galleries
- Past retreat memories
- Testimonial videos
- Improved donation stories
- Guided journey page
- FAQ
- WhatsApp community QR code
- Better mobile layout
- SEO improvements

## Phase 3: Hosting and Deployment

Goal:
Make the website production-ready.

Potential options:

- GitHub Pages for simple demo
- Vercel for fast Next.js deployment
- Azure Static Web Apps for Azure-aligned hosting
- Azure Blob Storage for media later

Decision rule:

Use the simplest hosting that helps WayToMoksha go live sooner.

Do not overengineer hosting during early development.

## Phase 4: Volunteer Management System

Goal:
Build Project 2.

Features:

- Volunteer intake
- Human onboarding flow
- Role assignment
- Availability logging
- Recurring availability
- Temporary availability updates
- Volunteer categories
- Future task assignment

## Phase 5: Dream Analysis Workflow

Goal:
Build Project 3.

Features:

- Dedicated WhatsApp intake number
- Case creation
- Analyzer queue
- Follow-up questions
- Decoder assignment
- Response tracking
- Free monthly quota
- Future subscription support

## Phase 6: Mentorship and Subscription

Goal:
Future feature.

Potential benefits:

- More than five dreams per month
- Guided mentorship
- Structured learning journey
- Access to organized lessons
- Subscription-based support

This should not be built until the core website, volunteer system, and dream workflow are stable.

## Phase 7: Community Hub / WhatsApp Consolidation

Goal:
Build Project 4.

This is a long-term effort.

The goal is not to rebuild WhatsApp chat immediately.

The goal is to reduce the need for many separate WhatsApp groups by making the website the central source of truth.

Potential features:

- Community landing page
- Daily session hub
- Official announcements
- Retreat-specific pages
- Session links
- Community guidelines
- Future notification system

## Immediate Next Step

Start with Phase 1 only.

Build the public website using Cursor and AI-first development.
